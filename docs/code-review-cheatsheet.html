2看代码前先问四个问题

1
碰到红线了吗？
碰到 → 双人审 + 要回滚方案。
2
这个值有几个真相源？
时间 / 颜色 / 金额 / 配置 / 状态 —— 多于一个就是问题。
3
失败会怎样？
断网 / 超时 / 第三方拒绝 / 重复提交 —— 有没有明确归宿。
4
这个坑以前踩过吗？
踩过就必须有门禁，不能只靠注释。

3五个维度，逐条过

  • D1 正确性：金额整数分 · 写操作幂等 · 并发失败原样回滚 · 时间只在服务端 · 状态机四处同步 · 失败路径也设计过
  • D2 数据安全：租户作用域 · 房间号不出商户库 · 日志脱敏 · 密钥不下发客户端 · 新接口默认鉴权
  • D3 唯一真相源：配置走 ConfigResolver · 状态色走 Token · 金额走 amount.ts · 类型照抄服务端 · 判定不进前端 · VITE_* 会被内联进包，不得放秘密
  • D4 小程序交付：顶部用 useNavMetrics() + 行内样式 · 胶囊区不可点 · 组件必须 import · 异步三态齐全 · 骨架同高 · 文案中性 · 无硬编码色值
  • D5 可维护性：注释讲"为什么" · 无调试残留 · 依赖固定版本 · 一个 PR 一件事 · 新环境变量同步 .env.example

4看到这些直接给 blocker

前端自己算"能不能下单" 前端自己写 status → 颜色映射 金额出现浮点 写操作没有幂等键 日志打出地址 / 手机号 / 令牌 页面里出现 #RRGGBB 自定义导航页用 env(safe-area-inset-top) 顶部内边距用 class 写（会被 padding 简写覆盖） 模板用了组件但没 import .env.local 或密钥出现在 diff 里 把 tsc 换成 esbuild / tsx 跑服务端

5十条红线（不可协商）

R-1 钱不能错：账本变动必有流水，退款必回库 R-2 库存不能为负，预占失败必释放 R-3 房间号不出商户库，日志与平台出参脱敏 R-4 能否下单由服务端判定 R-5 状态颜色只能来自 Token R-6 样式不得硬编码色值 R-7 楼栋只能停用不能删除（DELETE 一律 403） R-8 密钥 / .env.local / AppSecret 绝不入库、不下发 R-9 提交色必过 guardThemeColor R-10 前端不解析后端 message，只按 code 分支

6门禁命令（PR 里必须贴完整输出）

# 全量 —— P0 / P1 必跑
npm run verify

# 分端
npm run verify:server        # 文案 + 构建 + 冒烟 119/119
npm run verify:mini          # Token 漂移 + 色值 + 引用完整性 + 类型 + 构建 + 组件注册

# 发布卡口：提审小程序前，产物里不得出现本机地址
npm run check:build -w @snack/mini -- --release

# 本机铺数据（内存库每次重启清空，重启后重跑）
npm run dev:server           # 另一个终端
npm run seed:dev
门禁全绿只说明没有低级错误，不构成任何质量背书 —— P0 改动仍然必须有人读懂逻辑。
