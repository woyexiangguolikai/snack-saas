# 运营手册

给**平台运营 / 客服**看的手册：怎么开一家新店、日常要盯什么、出了问题按什么顺序查。

面向另外两个角色的文档：商户自己看的在「店铺设置」页的就地说明里；
开发看的在 `README.md` 与各阶段验收记录里。

---

## 一、开一家新店（5 分钟）

1. **平台后台 → 租户管理 → 新建租户**
   - 填：店铺名、经营主体、小程序 AppID、学校（自动带出该校楼栋模板）、联系人、电话
   - 学校模板决定这家店一开始有哪些楼栋；没有对应学校就先在「学校模板」里加
2. **绑定店主微信**（易漏，漏了店主进不去商户端）
   - 平台后台 → 租户详情 → 绑定店主
   - ⚠️ 这一步必须是**显式**的。系统不会"第一个点『我是店家』的人自动成为店主" ——
     那样任何学生点一下就能拿到定价权
3. **让店主自己铺货**
   - 网页后台 → 商品 → 批量导入（4 步向导），或直接在小程序「商品」页加
   - 铺完库存后学生端才能看到东西；只建商品不铺库存，学生看到的是"今天没有可卖的"
4. **确认两道闸门是开的**
   - 平台后台 → 租户详情：服务期（订阅）有效、服务费余额 > 0
   - 任一道关着，学生端统一显示「店铺暂未营业，商品可以先看看」——
     **这是刻意设计的**：学生不该知道店家是"欠费"还是"到期"（AC-13）

**审核前必做**：跑一次 `npm run seed:demo` 预置演示数据。
需求 v0.4 细节 37 明确写了：**空壳小程序审核大概率驳回**。

## 二、日常要盯的四件事

### 1. 对账看板（每天一次）

平台后台 → 对账。看两个数，它们**必须分开看**：

| 差额 | 含义 | 处理 |
|---|---|---|
| 支付差额 | 钱对不上（支付成功但没登记 / 登记了没到账） | 查支付回调；孤儿支付会**自动告警** |
| 库存差额 | 货对不上（流水与实际库存不符） | 查库存流水；通常是有人绕过了库存原语改数 |

孤儿支付（收到钱但找不到订单）**只记录 + 告警，绝不自动编单** ——
自动编一单出来，等于把"不知道是谁付的钱"变成"看起来是某人下的单"，
后者无法撤销。

### 2. 监控告警（有告警就看）

五类告警：密钥失效、推送失败、对账差额、库存异常、租户异常。
告警按**自然日幂等** —— 同一天重复巡检不会刷屏（否则一天 48 条一模一样的告警，
看的人很快就学会忽略所有告警）。

### 3. 服务费余额（每周一次）

余额触底 → 店铺自动停止接单，充值后**立即恢复**，无需其他操作。
已下单的订单不受影响。学生端看到的是"店铺暂未营业"（不会说"欠费"）。

### 4. 服务期到期（到期前 15 / 7 / 3 天会提醒）

到期后：商品仍可浏览，下单关闭，续费即可继续。

## 三、出问题怎么查（按这个顺序）

### 学生说"下不了单"

先问**哪一栋**，再按序查：

1. 店铺开着吗（商户端 → 店铺设置）
2. 那一栋**今日停送**了吗（商户端 → 楼栋）
3. 时间窗：是否已截单 / 是否营业时段
4. 服务期与余额（平台后台 → 租户详情）

学生端这四种情况都是**同一句灰话**（AC-02：截单用灰不用红；AC-13：经营信息不透露给学生）。
所以学生自己看不出是哪一种 —— 需要运营按上面顺序查。

> 顺带一条常见误判：商户说"我把这栋停送了，怎么库存还在"。
> **停送 ≠ 清库存**（AC-17）。停送后库存数字保留、恢复配送后自动生效，
> 界面上写了这一句。这是对的，不是 bug。

### 学生说"付了钱但订单没成"

1. 平台后台 → 对账，看有没有**孤儿支付**
2. 有 → 说明钱到了但订单没匹配上，按告警里的流水号处理
3. 没有 → 让学生截支付凭证，查该订单状态；超 15 分钟未支付的订单会被自动关单并释放库存

### 商户说"我没点送达，订单自己变成已送达了"

配送中的订单超过 **12 小时**未标记送达，系统会兜底置为已送达，
并在订单详情里写明"本单由系统自动置为已送达"。
这是为了防止配送清单里永远挂着几单旧状态。

### 商户说"余额扣得不对"

每日 **01:00**（中国时区）跑一次扣减，按业务日汇总。
同一天重复跑不会重复扣（幂等键 = 业务日 + 租户编码）。
查「账单」页看当天的明细。

## 四、不能做的事（做了会出事）

| 不要 | 原因 |
|---|---|
| 帮商户把停送的楼栋**删除** | 楼栋只能停用不能删除（§4.8）—— 删了历史订单就指向一个不存在的楼栋 |
| 在数据库里直接改库存数字 | 库存流水会缺条，对账差额报警且**无法事后补救**；要走库存原语 |
| 把平台后台的主题色调成某商户的色 | 平台后台必须中性（AC-12），有护栏脚本会拦 |
| 在平台后台查学生房间号 | 房间号不出租户库（AC-13），数据层就不返回，这是硬约束 |
| 手工"补一单"来消化孤儿支付 | 见上：会把"不知道谁付的"变成"看起来是某人下的"，且不可撤销 |

## 五、常用命令

```bash
npm run start:server     # 起服务端
npm run seed:demo        # 铺演示数据（送审前必跑）
npm run seed:dev         # 铺本机开发最小数据
npm run smoke            # 服务端冒烟（改完代码跑一次）
npm run verify           # 全量校验（文案护栏 + AC 护栏 + 冒烟 + 三端构建）
npm run stress           # 压测（并发下单 / 回调幂等 / 库存守恒）
```

⚠️ `DB_MODE=memory` 下**重启服务端数据即清空**，重启后重跑 seed 脚本即可。
生产必须换成真实数据库。
