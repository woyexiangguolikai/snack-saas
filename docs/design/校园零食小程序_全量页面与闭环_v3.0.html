06闭环校验矩阵（42 条逐条过）

§00.2 列的是"链路是否完整"，本节要回答的是更硬的问题：每条闭环的每个界面元素，是否都有数据来源；每个状态的出口，是否都能落到一个稳定态而不断链。三张表竖着读就是一条闭环的完整生命周期。

6.1 三条判据

判据一

页面无缺

闭环里的每一步都指向一个已交付页面。不存在"跳到一个还没画的页面"。表中"链路"列的每个箭头，两端都是 §01–§04 里的页面编号。
判据二

字段可溯

界面上的每个动态值都能在 §05 字段字典里找到来源库与格式。"字段链"列写的是跨页必须带过去的键——丢了它，下游页面就会显示空白或默认值。
判据三

出口不断

每个状态都必须有至少一条"继续往下走"的路。断链 = 死路：没有出口的状态，用户只能退出重进，这是最贵的失败。
结论

42 / 42 通过

这份清单不是"建议"，是复刻完成后的判定依据。任何一项不通过，就不算做完。前 3 条是上一轮确定列为正式验收项的"最容易被做走样"的三处；其后是本轮新增的验收项。

7.1 三处易走样点（上轮确认为正式验收项）

AC-01

楼栋牌不得被"改造"

必须：高 44px、圆角 10px（r-md 20rpx）、brand-500 实心、白字、无阴影无描边。
禁止：改成圆角矩形片、加投影、加渐变、改成胶囊。
为什么：它在本产品出现 6 个位置，是唯一的"签名组件"。一旦各页各画一版，用户就失去了"看到它就知道我在哪栋楼"的条件反射。
AC-02

「已截单」必须用灰色

必须：灰色 + 时钟/结束类图标 + 明确恢复时间。
禁止：改成红色、橙色警告、加感叹号。
为什么：红在本系统里独占"需要人动手"。截单是每天发生、次日自动恢复的正常节律，用红会制造无谓紧张，并稀释真正需要动手的红（如余额预警、对账差额）。
AC-03

配送清单不能被退回成"订单列表"

必须：空间序 —— 按楼栋分组 → 楼层 → 房间号排列，单位是"一趟/一栋"，每行可整体勾选，勾完折叠成绿色"已全部送达"行。
禁止：按时间倒序、按订单号、加"由新到旧"切换、把勾选做成逐项小复选框而没有行级热区。
为什么：订单列表回答"谁刚下单"（时间序），配送清单回答"这趟先去哪间"（空间序）——这是两个视图，不是一个视图的两种排序。退回成订单列表，等于把 v0.4 最核心的履约模型改动扔掉。
