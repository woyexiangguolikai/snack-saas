变量用途使用规则
brand-500主按钮底、楼栋牌底、选中 Chip 底、TabBar 选中全站唯一的"可点击主色"。同一屏内出现超过 2 处 brand-500 实心块即为视觉失焦，需要复查
brand-600 / 700主按钮悬停、品牌色文字白色背景下需要承载文本时必须用 700，因为 500 与白的对比度只有 3.2:1，不满足正文 4.5:1
brand-100 / 50选中行底、图标底、轻高亮不得用于强调"错误"，错误一律用 --danger-bg
brand-300禁用态主色、虚线分隔只表示"不可用"，不表示"危险"
换肤护栏（强制实现）：商户提交的主题色不允许直接使用。服务端生成九级色阶后必须校验 brand-600 与白字的对比度：
· 对比度 ≥ 4.5:1 → 直接采用
· 3.5:1 ≤ 对比度 < 4.5:1 → 整体加深一级（把 600 的值降为新的 500，其余按比例下移）
· 对比度 < 3.5:1 → 整体加深两级，并给商户一句人话提示：「这个颜色偏浅，为了白字看得清，我们稍微调深了一点」
不允许出现"提交什么就用什么"的实现——那会导致白字按钮在浅色主题下彻底看不清。

语义色唯一含义允许出现的位置（超出范围即违规）
danger需要人立刻动手待接单计数、余额低于预警线、库存为 0 的格子、不可逆操作的确认按钮、表单错误。不允许用于：已截单、未覆盖、休息中、普通提示
warn即将需要动手，但现在还来得及即将截单（剩余 < 30 分钟）、低库存（≤ 预警值）、订阅剩余 ≤ 7 天、上传流水线卡点
ok已闭环，无需任何动作已送达、营业中、余额充足、支付成功、导入成功
info纯告知，不需要动作配送中的进度说明、系统公告、字段填写指引
off不可用，但不危险已截单、本栋停送、休息中、未上架、禁用控件、历史归档记录
这个"唯一含义"表是整套状态语言的锚。只要每个状态色只有一个含义，用户就能在不读文案的情况下判断"我要不要动手"。一旦 danger 被用来表达"今天做完了"，这个判断能力就失效了——这正是上一轮确认的「已截单不用红」的底层理由。

时长用于缓动约束

02原子组件

14 类基础零件。原子组件不带业务语义——只认主/次/危险/禁用，不认"接单/送达"。业务语义由 §03 的签名组件承载。每类给出六个必备状态的完整规格。

通用六态定义（所有可交互组件都必须实现）： 默认 → 按压（用户手指已按下，尚未抬起） → 聚焦（表单类，键盘已唤起） → 禁用（当前条件下不可用） → 加载（动作已提交，等待结果） → 错误（校验未通过或服务端拒绝）。

04反馈与浮层

反馈组件决定"用户知不知道自己刚才那一下有没有生效"。本产品只在四个地方使用浮层：轻提示、确认、抽屉、动作面板。凡是能用页面解决的问题，不用浮层。

浮层使用总则： ① 可逆操作不给浮层（改库存、勾选送达、加购）——给轻提示或撤销条即可；
② 不可逆操作必须给确认（关店、停用楼栋、取消订单、删除地址），且正文要写清影响范围；
③ 一次只允许一层浮层。禁止"弹窗里再弹抽屉"；
④ 抽屉只从底部升起，不使用居中弹窗承载长内容。
