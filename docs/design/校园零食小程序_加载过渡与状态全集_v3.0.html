加载 · 过渡 · 状态全集

一半的真实使用发生在"事情不顺利"的时候：网络慢、数据没到、没有数据、时间窗关了。
本文件把这四种情况全部设计出来 —— 任何没有设计的状态，最终都会变成白屏或「操作失败」。

加载体系总览：什么场景用什么

这是本文件最重要的一张表。开发时先查这张表，再决定用哪种加载方式——不要一律用转圈。

场景使用时长理由
App 冷启动启动闪屏（品牌页）≤ 1.5s启动时的空白会让用户以为没反应。闪屏是唯一允许"只放 logo"的地方
租户解析中品牌骨架屏（首页骨架）200–800ms解析期间用户已在等，直接给首页骨架比给转圈更快到达"有事可做"的感觉
页面首次进入骨架屏（结构一致）任意骨架让用户提前看到"这页有什么"，且数据到达时布局不跳动
页面内局部刷新局部骨架（只替换内容区）任意不要整页骨架——会把用户已经看到的内容清空
翻页 / 加载更多底部行内 loading任意列表底部出现三行骨架 + "正在加载"，不用全屏
下拉刷新顶部指示器≥ 600ms即使数据很快返回，也要停留 600ms——否则用户看不到"刷新过"
按钮提交按钮内 loading任意锁住按钮防重复提交，文案改进行时
支付跳转前后支付中转页任意微信支付唤起有 1–3 秒延迟，必须有中间态承接
批量长任务进度条 + 百分比 + 可离开数分钟推送 37 个租户、导入 500 行 Excel：不能让人干等
全屏阻塞（极少）遮罩 loading< 3s只在"必须等待且不能做其他事"时使用。本产品只有 2 处
无数据空状态（说明 + 下一步）—见 §04。任何空状态必须给出下一步
失败错误态（原因 + 重试）—见 §05。禁止只写"操作失败"
三条不可违反的加载规则：
① 首屏数据未到时，禁止"白屏 + 居中转圈"。必须用与该页结构一致的骨架屏（AC-06）；
② 禁止整页骨架用于局部刷新。已经看到的内容不能被清空；
③ 骨架块的尺寸必须与真实内容一致。不一致会导致数据到达时布局跳动，比没有骨架更难受。

04空状态（12 种）

空状态是"用户第一次面对产品"的最高频场景。每个空状态必须同时具备：说明为什么空 + 一个可点的下一动作（AC-07）。禁止只放插画和"暂无数据"。

本产品空状态的特殊性：大部分"空"不是用户的问题，而是系统状态造成的——该楼栋没上架、今天已截单、还没营业。这类空状态必须解释系统为什么空，否则学生第一反应是"这个店是不是坏了"，商户第一反应是"系统出错了"。「本店暂未覆盖」比「暂无楼栋」多给了用户一份"这不是我操作错了"的确认。

05错误与网络态

错误处理的原则只有一条：让用户知道发生了什么、以及他还能做什么。做不到这两点，就等于把问题丢给了客服。

AC-12 全局文字审查：以下文案不得单独出现——「操作失败」「系统错误」「未知异常」「请稍后重试」「网络异常」「请求失败」。每处错误必须是原因 + 下一步的结构。实现完成后用全文检索逐条核对。

5.1 页面级加载失败

① 页面级失败三要素：说清哪部分失败（"商品"而不是"页面"）+ 可能的客观原因（网络）+ 哪些状态被保留了（选好的楼栋）。第三点很关键——用户最怕的是"重来一次要重新选楼栋"。

这些商品没加载出来
已显示的可以直接下单。缺失的 6 个商品可以单独重试。
只重试这部分

② 局部失败（最重要的一个）部分接口失败时不能把整页判为失败。已经拿到的内容继续可用，失败的区块单独提示并可单独重试。「已显示的可以直接下单」这句话必须写——否则用户会以为整页都不安全而离开。

5.2 网络横幅（最高优先级，任何情况下可见）

网络已断开，已改为离线浏览
网络较弱，正在重试（第 2 次）

网络横幅优先级 z-80。绝不"清空页面"——断网时页面内容保持可见，只是不能提交。恢复后显示 2 秒绿色条再消失，给用户一个"刚才那个问题解决了"的确认。

07动效规范与微交互清单

动效在本产品里只服务一件事：让"刚才那一下生效了"变得可见。它不服务娱乐性，也不服务品牌表达。

7.1 三条原则

① 时长必须短于感知阈值。高频动作（加购、勾选、切楼栋）的反馈必须在 150ms 内完成，超过这个时长就会产生"卡"的感觉。
② 只动必须动的东西。不做整页转场、不做元素飞入、不做列表交错入场。这些在第一次看时是"高级感"，第十次看时是"慢"。
③ 禁止弹性回弹。零食下单是高频短时动作，回弹会拖慢节奏，与"快"的品牌承诺矛盾。

7.2 时长与缓动总表

时长缓动用于约束
80msease-out按钮按压缩放（scale .985）、复选勾选绘制不做位移，避免在滚动列表中误触发
150msease背景色变化、Chip 选中、Tab 切换、库存格状态切换只动 background / color / border-color，这三项走 GPU 合成
200msease开关滑块位移（与背景色同步）两者时长必须一致，否则滑块会"飘"
220msease-out骨架屏淡出与内容淡入、勾选后行折叠、批量条升起折叠必须同时改 max-height 与 opacity，否则会闪
280mscubic-bezier(.32,.72,0,1)弹窗出现、抽屉升起、撤销条滑入、Toast 淡入位移起点不超过屏高 60%

10数据加载完成骨架 220ms 淡出，内容 220ms 淡入（交叉）必须交叉，不能先消失再出现，否则会看到一瞬间白屏
11下拉刷新指示器展开 + 弹性回弹（唯一允许的弹性，因为它是手势跟随）手势跟随的物理感是必要的，它不属于"界面动效"
12确认弹窗遮罩 200ms 淡入 + 卡片 280ms 缩放（.94 → 1）缩放起止差异要小，过大像"蹦出来"

14长任务进度进度条宽度 400ms 缓动；日志逐行追加，不重排日志重排会让运营看不清正在发生什么
15tab 切换图标线性↔面性 150ms 切换，无滑动指示条不做滑动指示条：TabBar 是页面导航，不是内容分页

7.4 性能与无障碍约束

约束要求说明
可动画属性只允许 transform / opacity / background-color / color / border-color禁止动画 width / height / top / left / margin——会触发重排，低端安卓机上必然掉帧
折叠动画max-height + opacity这是唯一允许动画 max-height 的例外，因为折叠必须改变高度
减少动效prefers-reduced-motion: reduce 时：所有位移改淡入淡出，时长减半，骨架扫光取消对前庭敏感用户，位移是最难受的一类动效
骨架扫光列表超过 20 个骨架块时用静态 line-100大量元素同时扫光会造成明显的性能压力与视觉噪点
遮挡检测聚焦输入框时自动滚动，cursor-spacing = 20键盘不得遮挡正在输入的字段
长列表订单列表、配送清单、库存矩阵使用虚拟滚动或分页库存矩阵 50 SKU × 5 栋 = 250 个可编辑单元格，全量渲染会卡
图片缩略图使用 webp，列表图片懒加载，占位尺寸与真实一致尺寸不一致会导致滚动时抖动
